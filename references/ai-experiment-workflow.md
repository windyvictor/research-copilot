# AI 辅助基线复现与实验

用于实现、复现或改进算法。先确定任务是写方案、写代码还是实际运行；写方案不意味着已经执行实验。

## 输入与验收

先读取论文、现有代码、数据说明和计算资源。沿用已知信息，只追问会改变实现或评估的缺口。

| 输入 | 要确定的内容 |
|---|---|
| 研究问题 | 要验证哪个主张，比较什么方法 |
| 数据 | 获取权限、版本、样本单位、标签和时间范围 |
| 基线 | 论文或代码来源、版本、目标结果的位置 |
| 评估 | 划分、指标定义、调参预算、重复运行方案 |
| 资源 | 环境、硬件、时间和费用边界 |

验收分为代码可运行、实现与论文一致、结果在约定条件下可复现。三者分别报告，不能用“跑通”代替复现成功。目标表格按论文实际内容选取，不固定为 Table 1。

## 数据与基线

1. 先检查样本单位、缺失、重复、异常及标签来源，再选清洗方法；保留原始数据和处理记录。
2. 在拟合预处理步骤前确定训练、验证与测试划分。插补、标准化、特征选择等参数只在训练部分拟合；交叉验证时在各训练折内拟合。时序或分组数据按其结构划分。
3. 优先核对作者实现；重新实现时，记录模块与公式、算法步骤的对应关系，以及无法确认的细节。
4. 先用小样本检查维数、损失和指标计算，再运行约定规模。随机种子与环境版本均记录；固定一个种子不等于证明结果稳定。
5. 保留配置、运行命令、日志和原始结果。失败、超时、缺数据均保留状态，不填造指标。

预处理规则参考 [scikit-learn 数据泄露说明](https://scikit-learn.org/stable/common_pitfalls.html)。实际调用参数以所用版本文档为准。

## 泄露审计与复现记录

划分前检查重复样本、同一主体的多次记录、时间先后及标签生成方式。目标泄露不仅来自预处理，也可能来自预测时不可得的字段。交叉验证中的插补、筛选和调参均不能接触外层测试折；最终测试集不用于反复挑模型。发现污染后重新定义划分并重跑相关结果，不能只删掉一段描述。

每次实际运行记录数据版本或哈希、划分规则、代码版本、依赖、硬件、种子、命令、配置、状态和结果文件。指标写清方向、聚合方式及不确定性来源。先小样本跑通，再运行目标设置；记录偏离作者设置的地方及可能影响。

验收分开判断：材料可获取、代码可执行、实现符合目标、结果支持主张。不能只因仓库存在就称可复现。结果相近的容差按指标、随机波动和原文报告精度说明，不事后选择最有利种子。

## 改进与消融

先解释基线的具体失败情形，再提出能检验该解释的最小修改。注意力、多尺度、损失函数或训练策略只是候选，不按模板一律叠加，也不把指标提升自动解释为创新。

比较时核对数据、预处理、训练预算、调参机会和指标口径。不能统一的条件单独列明。SHAP、LIME 等解释工具按问题需要选择，其输出不能替代机制证明。

消融配置须明确回答哪个问题。三个二元模块的全因子设计有 8 种组合；Full、−A、−B、−C、Base 是其中 5 种。预算只允许部分组合时，报告实际覆盖范围，不能声称检验了全部交互作用。

长时间运行先做规模与预算估计。执行以当前任务授权和资源上限为准，不因为模板写着“自动跑完”就启动超出范围的作业。

## 图表与交付

图表从真实结果文件生成，保留单位、样本量、指标方向与不确定性的定义。按目标载体选择矢量或栅格格式；是否使用网格、双轴以及分辨率，按图的用途和期刊要求决定。

方案任务交实验设计与验收条件。实现任务交代码和实际验证结果。运行任务附命令、配置、结果位置与复现差异；未运行部分明确标注。达到约定目标后结束，不自动扩展新模型或更多实验。

## 可复用任务描述

请依据提供的论文、代码和数据说明，核对目标方法与评估协议。先完成最小基线，再依据已观察的失败情形提出改进。记录实现假设、数据划分、运行配置和实际结果；缺失的条件列出，不补造数值。只执行当前任务要求的实现或运行范围。
